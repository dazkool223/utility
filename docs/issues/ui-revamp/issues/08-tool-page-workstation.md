# 08: Tool page workstation

**What to build:** A Tool page opens with a slim header: the Category colour edge, the Tool name, a one-line description, an icon-only Favourite control and a "works well with" menu built from the Tool's related Tools. The working area fills the available width and height with dense monospace panes and neutral surfaces, and the options bar attaches to the panes like a tray. A Restriction shows as a clearly designed notice before the user starts, and the user may still proceed. The Heavy Tool first-use note appears only in the header.

**Blocked by:** 01 (Warm theme and fonts foundation), 04 (Category identity).

**Status:** ready-for-agent

- [ ] The header shows the Category colour edge, name, description, an icon-only Favourite and a related-Tools menu
- [ ] Toggling Favourite works and the state is visible, using the accent token
- [ ] Input and output panes use the full available width and height on large screens and stack sensibly on small ones
- [ ] The options bar is visually attached to the panes
- [ ] Restrictions appear before the user starts as a designed notice, and Tool use is not blocked
- [ ] The Heavy Tool engine-download note appears only once, in the header
- [ ] Keyboard shortcuts for run and copy output keep working
- [ ] Existing per-Category Tool end-to-end specs pass
